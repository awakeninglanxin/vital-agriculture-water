## 一、为什么想到「逆M水滴」

网页 hero 区原本画的是一个手工 SVG 水滴（两段三次贝塞尔 + 底部圆弧），线条生硬、被老师判定「太丑」。

水滴的经典数学来源之一是**曼德博集（Mandelbrot set）主心形（cardioid）的单位圆反演**：

- 经典 M 集主心形参数式：

  ```
  c(θ) = e^(iθ)/2 − e^(2iθ)/4
  ```

- 对其取倒数（`c → 1/c`，即单位圆反演 + 实轴共轭）后，得到一条**逆M主心形**曲线，形状恰好是**水滴（teardrop）**：

  ```
  c_inv(θ) = 1 / ( e^(iθ)/2 − e^(2iθ)/4 )
  ```

- 两个特征点：
  - **根点（A 点）**：`c = −4/3 ≈ −1.333`，位于水滴「底部」最左端；
  - **尖端（B 点）**：`c = +4`，位于水滴「尖端」最右端（尖端朝右、正 x 轴）。

水滴 = 逆M主心形上半弧 → 沿实轴镜像 → 完整闭合曲线。解析上纯干净，这就是我最初想走「数学解析精确轮廓」这条路的原因。

## 二、现成代码：bat → py 管线

老师提示「研究逆M水滴很久了，那是有现成代码的」，于是找到现成的生成管线：

| 解析生成器 | 同目录下 `generate_droplet_analytic.py` | 计算逆M主心形轮廓 + matplotlib 出图 |

**bat 关键内容**（GBK + CRLF，`chcp 65001` 声明 UTF-8）：

```bat
set PY=C:\Users\ThinkPad\.workbuddy\binaries\python\versions\3.13.12\python.exe
"%PY%" generate_droplet_analytic.py -n 1200 -e 5
```

**生成器核心公式**（`generate_droplet_analytic.py`）：

```python
def inv_cardioid(theta):
    c_cls = 0.5 * np.exp(1j * theta) - 0.25 * np.exp(2j * theta)
    return 1.0 / c_cls
```

参数含义：
- `-n 1200`：主心形采样点数；
- `-e 5`：尖端加密比（尖端附近用 `θ^1.5` 非线性加密，避免尖点折线化）。

输出三件套（同目录）：
- `droplet_invM_analytic.txt`（空格分隔 x,y）
- `droplet_invM_analytic.csv`（逗号分隔）
- `droplet_invM_analytic.png`（matplotlib 填充 + 轮廓 + 尖/底标注）

**关键事实**：这个生成器是**纯解析式，没有 M 参数**。老师提到的「M=15 对应的水滴轮廓」其实是另一套 **Farey 种子分析**（`downsample_bulb_anchor` 里用 period-1~7 泡锚点 + `2^n+φ(n)` 权重降采样），与主生成器 `generate_droplet()` 是两条独立路径——M=15 并不直接对应这个解析轮廓，这是当时定位「M=15」没找到的直接原因。

## 三、尝试过程（按时间顺序）

### 尝试 1：手推逆M → 转 SVG path（失败）

- 写了 `gen_droplet.py`，用 `cr2bezier()` 把解析轮廓拟合成三次贝塞尔，生成 SVG path。
- **报错**：`c1, c2 = cr2bezier(...)` → `too many values to unpack`。
  - 根因：`cr2bezier` 返回的是**四个坐标**（`c1x, c1y, c2x, c2y`），不是两个点。
  - 修复：改为 `c1x, c1y, c2x, c2y = cr2bezier(...)`。

### 尝试 2：插入 SVG path 到网页（视觉不达标）

- 写了 `apply_droplet.py`，把生成的轮廓写入 hero `<svg>`：
  - outer 路径 7421 字符、inner 路径 7435 字符，替换掉原来的短 path `M180 28 C...`。
- 结果：路径是「精确」了，但**点太密、视觉像锯齿多边形的描边**，且单个 SVG 里塞 7400+ 字符 path 不优雅，效果仍然达不到「好看」的标准。

### 尝试 3：定位「M=15」（未果）

- 按老师提示去找 M=15 的轮廓，翻遍 `generate_droplet_analytic.py` 确认**无 M 参数**。
- 结论：M=15 属于另一套 Farey 种子降采样分析，不在这个主生成器里。这条线索到此为止。

### 尝试 4（老师拍板）：放弃逆M，两图融合

老师原话：「实在不会弄那个逆M 你可以用两图融合一下生成一个图平替网页首页右侧你画的像水滴的图。」

改用 **PIL 图像融合**方案：

| 输入图 | 来源 | 用途 |
|--------|------|------|
| `水滴1.jpg` | 万花筒/光晕底图 | 做**柔光晕背景** |
| `水滴2.jpg` | 彩色水滴主体 | 做**主体** |

处理流程（`fuse_droplet.py`）：
1. 水滴1 中心裁 720×720 → 高斯模糊 `r=22` → 去饱和 `0.55` → 提亮 `1.15` → 径向 alpha 羽化遮罩；
2. 水滴2 裁掉底部阴影 + AI 水印 → 作为主体叠在光晕之上；
3. 合成到 RGBA(720×900) 画布 → 最终裁 720×800 透明底。

产物：`图片素材/水滴_fused.png`（720×800 PNG，透明底，169 KB）。

### 收尾：清理残留孤儿 SVG

- 把 hero `<svg>` 开头替换成 `<img src="图片素材/水滴_fused.png" ...>` 后，原 SVG 的 `<defs>`/渐变/path/螺旋/土壤条**残留成了孤儿 HTML**（16954 字符）。
- 第一次 `cleanup_svg.py` 用正则 `        <defs>.*?</svg>` 只删了 397 字符（匹配到了错误的更早片段）。
- 第二次 `cleanup_svg2.py` 改成**锚点跨度删除**：定位 `alt="活水滴：涡旋内爆·微质子固化波"` 的 `<img>` 结束 `>`，再找下一个 `</svg>`，删掉两者之间全部内容——成功清干净。

## 五、结论

1. **数学上**：逆M主心形反演 `c_inv(θ)=1/(e^(iθ)/2−e^(2iθ)/4)` 确实能生成精确水滴，尖点 c=+4、根点 c=−4/3，是「好看水滴」的严谨来源。
2. **工程上**：7400+ 字符的密集 path 塞进网页不优雅、视觉不达标，且 `generate_droplet_analytic.py` 无 M 参数（M=15 属另一套 Farey 分析），继续死磕收益低。
3. **最终落地**：按老师指示改用 PIL 融合两图，`水滴_fused.png`（万花筒柔光晕 + 彩色水滴主体）已平替 hero 手绘水滴，孤儿 SVG 清理干净。
4. **经验**：遇到「数学精确但视觉难看」的图，图像融合/实拍图往往比解析 path 更省时、效果更好——先把现成代码跑出来看效果，再决定是否手推。
